# Grdlabs — تطبيق التلفون

تطبيق الآيفون والأندرويد لموظفي الشركات اللي تستخدم برنامج Grdlabs على الحاسوب. مبني بـ Expo (React Native)، ويستخدم نفس Firebase ونفس قواعد الحماية (`reference/firestore.rules`) اللي يستخدمها `grdlabs.site/app`.

## شنو يسوي

- **الربط بالشركة مرة وحدة:** المدير يطلع رمز ربط (QR) من برنامج الحاسوب. الموظف يمسحه بالتطبيق، أو يلصق الرابط، ويسوي حساب بإيميل وكلمة سر. إذا الإيميل غير مؤكد، ينطلب كود يوصل على الإيميل.
- **الدخول من أي تلفون** بنفس الإيميل وكلمة السر.
- **الحضور والانصراف:** الموظف يضغط الزر ويقرّب التلفون من ملصق NFC مالت الشركة. بعدها يأكد بـ Face ID أو البصمة، والتطبيق يتأكد إنه داخل حدود الشركة بالـ GPS. Firestore يرفض أي بصمة من برّا الحدود.
- **الراتب والسلف والخصومات والمكافآت وسجل الحضور:** كل موظف يشوف بياناته هو بس.

## الملفات

| الملف | شنو بيه |
|---|---|
| `App.tsx` | تشغيل التطبيق، والتنقل بين الدخول والربط والشاشات، وفتح روابط QR والملصق |
| `src/account.ts` | كل التعامل مع Firebase: الدخول، الربط، تحميل الراتب، تسجيل الحضور، كود الإيميل |
| `src/device.ts` | Face ID والبصمة، والـ GPS، وقراءة ملصق NFC |
| `src/screens/Auth.tsx` | شاشات الدخول، ومسح QR، والتسجيل بالرمز، وكود الإيميل |
| `src/screens/Employee.tsx` | شاشات الموظف الخمسة وتسجيل الحضور |
| `src/ui.tsx`, `src/theme.ts` | تصميم Liquid Glass من النموذج السابق (`reference/prototype.html`) |
| `site-files/.well-known/` | ملفات تنحط على grdlabs.site حتى روابط الملصق والـ QR تفتح التطبيق مباشرة |

## تجربة الشاشات بالمتصفح

```bash
npx expo export --platform web && python3 -m http.server 8737 --directory dist
```

بعدها افتح `http://localhost:8737/?demo`، وتطلعلك الشاشات ببيانات تجريبية. أما الكاميرا والـ NFC والـ Face ID فتشتغل بس على التلفون.

## البناء والرفع على المتاجر

ما تحتاج Xcode ولا Android Studio، لأن البناء يصير على سيرفرات Expo (EAS).

1. سوّي حساب مجاني على expo.dev، وبعدين:
   ```bash
   npx eas-cli login
   npx eas-cli init
   ```
2. **نسخة تجريبية للأندرويد (APK):** تنزّلها على أي تلفون مباشرة:
   ```bash
   npx eas-cli build --platform android --profile preview
   ```
3. **نسخة المتاجر:** EAS يطلب منك تدخل حساب Apple Developer ويسوي الشهادات بنفسه:
   ```bash
   npx eas-cli build --platform all --profile production
   ```
4. **الرفع:**
   ```bash
   npx eas-cli submit --platform ios
   ```
   ```bash
   npx eas-cli submit --platform android
   ```

### قبل الرفع

- **ملفات الروابط:** بدّل `TEAMID` بـ Team ID مالتك من developer.apple.com، وبدّل `SHA256_FROM_EAS_CREDENTIALS` بالبصمة اللي يطلعها الأمر `npx eas-cli credentials`. بعدها ارفع مجلد `site-files/.well-known` لمستودع `grdlabs-site`.
- **App Store:** رابط سياسة الخصوصية `https://grdlabs.site/privacy/` ورابط الدعم `https://grdlabs.site/support/` موجودين. ولازم تعطي Apple حساب موظف تجريبي حتى يراجعون التطبيق.
- **Google Play:** عبّي نموذج «Data safety». التطبيق يجمع: الإيميل، والموقع (بس وقت البصمة)، والراتب.

## المرحلة الجاية: المحاسب والمبيعات وصاحب الشركة

برنامج الحاسوب بيه أصلاً صلاحيات (مدير، محاسب، مبيعات) ورموز دعوة `GRD-…`. بس بياناتهم (الفواتير، المصاريف، الزباين) ما تنرسل لـ Firebase، فالتلفون ما يكدر يشوفها. حتى نكمّل هذا الجزء نحتاج كود برنامج الحاسوب 1.9.x، حتى نضيف:

1. إرسال البيانات لـ Firebase، كل صلاحية حسب اللي يحق لها تشوفه (نفس فلترة `view()` اللي بالبرنامج).
2. قواعد Firestore لهذي البيانات.
3. شاشات المحاسب والمبيعات بالتطبيق، وتصاميمها موجودة بالنموذج.
